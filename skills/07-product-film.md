# 产品发布级视频制作规范

这套规范来自对 Apple、Linear、Stripe、Vercel、Raycast、Warp、Zed、Cursor 发布片的逐场拆解。
适用场景：**把一个 GitHub 项目当成产品来宣贯**，不是做成"技术科普"。

## 一、核心判断：空不空，看内容不看特效

顶级发布片几乎不用空态承载信息。**深色空是舞台，浅色空是白纸。**

所以顺序永远是：

1. **先把界面喂饱**（最高杠杆）
2. 再重构图（留白、圆角、阴影）
3. 再引导视线（光标、高亮环）
4. 最后才做舞台（深色底、光效）

反过来做——先加滤镜——只会让空画面变得更空。

## 二、五条硬规则

### 1. 不许裸图形

先放承载物（终端窗口、文件树、面板、真实截图），图形画在容器里。

裸方块、裸胶囊、裸时间轴 = PPT 圆角矩形。观众读不出"这是 git 快照"。

**反例**：一条线 + 四个方块讲快照。
**正例**：终端跑 `git log --oneline`，输出只有一条提交，快照从终端里被推出来。

### 2. 一个光源，三层结构

- 阴影统一 `0 18px 34px rgba(0,0,0,0.10)`
- 高光统一左上
- 背景层 / 承载层 / 主体层，三层缺一不可

### 3. 尺寸必须真

方块高度 = 真实文件数，胶囊宽度 = 真实窗口比例，字号 = 真实字重。
禁止随手 240×160。

### 4. 一句一元素

同一帧最多出现一个新元素，落定后静止 6 帧。
"先摆好再解释"是插图，"一句长出一个"才是动画。

### 5. 切点不许停在静止画面

这是"转场不高级"的真正原因，不是硬切的问题。

- 70–80% 硬切
- 3 个软转场只给章节缝（≤12 帧）
- 每镜一个主动作：6 静、5 推、2 拉、1 横移
- 推近落点必须是按钮 / 数字 / 代码行

Apple 把切点藏进运动（match cut），Linear 场间靠机位连续，Cursor 大量硬切但每切都在动。

## 三、视觉配方

### 浅色界面（跟随产品默认主题）

```
画布      #F4F4F6（不用纯白）
窗口      93% 宽
圆角      24
阴影      0 20px 32px rgba(0,0,0,0.13)
标题栏    保留产品自己的，不套假红绿灯
```

FredTalk 规范明确："真实软件截图保留原样，不套假窗"——套假窗＝伪造界面。

### 深色舞台（只给开场 / 章节 hero）

```
底色      #17171A（不用纯黑）
微光      radial-gradient(120% 90% at 50% 30%, rgba(120,110,255,0.10), transparent 62%)
窗口投影  0 50px 120px rgba(0,0,0,0.62)
```

深色舞台给 3–5 秒的 hero 就够，别整片换深色。

### 终端（代码类画面）

深色窗口 + 红黄绿三点 + 等宽字体。配色统一走 `kit.ts` 的 `term`，不要每组件各写一份。

## 四、转场配方

| 场景 | 做法 | 帧数 |
| --- | --- | --- |
| 章节缝 | `fade` | 10 |
| 硬切 | `pushCut`（两端 punch-in + 微闪） | 11 |
| 同一物体跨场 | 共享元素：叠一层绝对定位 Sequence，rect 插值 | 12–18 |
| 推穿 | A 场 scale 1→3 对准元素，切，B 场 scale 3→1 | 24 |

**不要**：整片叠化、大横移、"从远处慢慢漂过来"。

## 五、节奏

- 14 个镜头别等长。要 2 个 8–10 秒长镜（给证据/结论）+ 4 个 1.5–2.5 秒短镜（给功能点）
- 剪辑频率 10–13 次/分钟
- Linear 的 18 秒长镜头是"敢停"的证据

## 六、声音

- 配乐分段起伏：开场 0.34、中段 0.20、结尾 0.32
- **sidechain compress**：配音一说话音乐自动让位，阈值 0.035、比 6:1
- 首尾淡入淡出 2.2 / 2.5 秒
- 每个转场配声音锚点

## 七、字体与字幕

- 正片统一思源黑体（Noto Sans SC），400/500/700/900 四个字重
- 字体必须显式加载并 `delayRender`，否则第一帧是 fallback
- 字幕：白字 + `rgba(0,0,0,0.62)` 圆角底框，盒子跟文字宽度走

## 八、验收清单

- [ ] 每个抽象概念都有真实承载物，没有裸图形
- [ ] 每镜一个主动作，没有全程慢漂
- [ ] 切点都在运动里，没有切在静止帧
- [ ] 软转场 ≤3 个，其余硬切
- [ ] 界面留白处有真实内容，不是空态
- [ ] 字体统一、加载完成
- [ ] 配乐有起伏、配音处自动让位
- [ ] 音画时长差 < 0.2 秒

## 录屏镜头的世界级做法（2026-11 实战沉淀）

### 结论：不标注，只推镜

Apple / Linear / Stripe / Cursor 的真实界面镜头，**没有一个是靠外挂图形引导的**。
紫框、箭头、假光标、带底色的标签，这四样任何一样出现，画面立刻降级成 PPT。

正确的引导只有两种：

1. **推近**——把观众要看的东西放大到他没得选
2. **让元素自己亮**——极轻的一层柔光，不加边框

### 组件：`T126RecordedStage`

| 参数 | 作用 |
| --- | --- |
| `src` | 素材路径 |
| `startFrom` | 从第几秒开始取 |
| `shots` | 推近序列 `{at, x, y, zoom}`，`x/y` 是取景点在素材里的相对位置 |
| `zoomDuration` | 推近耗时，默认 1.5 秒 |

结构只有两层，**这是关键**：外层窗口位置和尺寸完全固定，内层视频做 `scale + translate`。
推近时窗口边界纹丝不动，只有里面的画面在变近——这才是"摄影机"而不是"画布缩放"。

### 素材要求（血泪教训）

- **必须用大视口录制**（如 `viewport: 3200×2000`），**不要**用 `deviceScaleFactor: 2`。
  Playwright 的 `recordVideo` 和 `deviceScaleFactor` 叠加会把界面挤到左上角，其余是灰块。
- 3200 宽素材可以安全推到 1.9 倍仍然锐利。1600 宽素材推 1.35 倍就到极限。
- 录制时动作要慢、要稳，一次只做一件事，方便后期定取景点。

### 节奏（4.5 秒一镜）

| 时间 | 做什么 |
| --- | --- |
| 0 – 0.5s | 窗口升起、对焦，留边完整 |
| 0.5 – 0.9s | 全景停一下，让观众认清这是哪 |
| 0.9 – 2.4s | 推近（1.2–1.8 秒，快出慢收） |
| 2.4 – 4.5s | 停住，让人读 |

**推完必须停**。推到位立刻切走，等于没推。

### 取景点的选法

`x/y` 是"要突出的那个东西在素材里的相对位置"，不是"窗口中心"。
素材里大片留黑是常态，取景点必须落在**有字、有色块、有 diff** 的地方，落在空白处等于什么都没推。

### 禁止清单

- 禁止紫框、红线、箭头
- 禁止合成假光标（真实录屏里本来就有光标，再叠一个是露伪）
- 禁止带底色的标签块
- 禁止把窗口推到露出背景（窗口边界不动就没有这个问题）
- 禁止推近后立刻切断，必须留静止段
