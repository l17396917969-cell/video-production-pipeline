# 一条视频是怎么做出来的

这份是流程回顾：我们实际怎么走的、卡在哪、哪些已经固化成规则。

---

## 一、六步流水线

| 步 | 谁做 | 产出 | 人要不要看 |
| --- | --- | --- | --- |
| 1 选题 | 机器给候选，**人定** | 一句角度 + 三个坑 | **要** |
| 2 素材 | 机器 | 真实录屏 / 截图 / 外部工具生成的图表 | 不用 |
| 3 写稿 | 机器 | 逐字稿 | 可以改 |
| 4 配音 | 机器 | 分句音频 + 字幕时间轴 | 试听 |
| 5 装配 | 机器 | 成片 | **要** |
| 6 发布 | 机器出文案，**人点发布** | 平台文案 + 封面 | **要点** |

人只做三个决定：**选题、确认画面、点发布**。

---

## 二、这条片子实际怎么走的

### 第 1 步：选题
选定 T3 Code（63k star 的开源 Agent 控制台），角度不是"它是什么"，而是
**"我花了两小时装上，它解决的不是写代码的问题"**。

### 第 2 步：素材（这一步花的时间最多，也最容易翻车）
- 官方页面截图 5 张（GitHub / 官网 / 产品界面 / 双端图 / README 片段）
- **自己装起来录屏**：`npx t3` 起服务 → 配对 → 建线程 → 派任务 → 等结果
- 录屏时踩的坑：Codex 桌面版装了不等于有命令行；MCP 配置报错会污染画面
- 后来又补录一次"多 agent 并行"（同时派 3 个 subagent 读 4 个文件）

### 第 3 步：写稿
16 句话、73.6 秒。结构是：判断 → 它是什么 → 坑一 → 跑通 → 关键设计 → 坑二 → 坑三 → 结论。

### 第 4 步：配音
Edge TTS（zh-CN-YunxiNeural），按分句出音频，再按字数分配时间轴生成字幕。

### 第 5 步：装配（返工最多的环节）
一共重剪 4 次：
1. 初版：29 镜，全截图推拉 → 被批"在放 PPT"
2. 二版：重写脚本走真实体验，加录屏 → 被批"实机太少"
3. 三版：33 镜，加转场和标注 → 被批"开场不吸眼球"
4. 四版：换专业开场 + SeeCode 出图表 → 当前版本

### 第 6 步：发布
出三平台文案，最后一步留给人点。

## 三、卡点清单（按代价排序）

| 卡点 | 代价 | 现在怎么解决 |
| --- | --- | --- |
| 素材不够，想拿排版糊弄 | 返工 3 次 | 素材不够就先去录，不录不剪 |
| 开场用抽象图形 / 仓库页 | 第一秒就输 | 用 SeeCode 式开场：项目名 + 数字滚动 + 真实界面打底 |
| 自己画图表 | 永远差一档 | 外部工具出 mp4（SeeCode），Remotion 只编排 |
| 整片纯黑底 | 压抑、廉价 | 底色 `#14141A`，浅色图表穿插形成明暗节奏 |
| 文案和画面不对位 | 听着 A 看着 B | 每段先写"这句指向什么对象"再选组件 |
| 同一素材反复用 | 观众看出在凑 | 统计 `props.src` 复用次数，>2 次就换 |

## 四、已经固化成规则的

### 内容判断（`rules/VIDEO.md`）
- 讲"我用了"，不讲"它是什么"
- 必须有：一个真踩过的坑、一个瓶颈判断、一句能被引用的结论
- 素材占比底线、纯文字卡片上限
- GitHub 项目的五拍开场

### 技术错误（`rules/MISTAKES.md`）
- 16 条技术坑（`sp()` 没加 px、SVG id 冲突等）
- 新增 C1–C8：纯黑底、抽象开场、仓库页、文案错位、界面太满、手搓图表、整片太暗、素材复用

### 组件库
- 96 个自研组件（`src/components/`）
- 外部素材容器 `T117`：播放 SeeCode 这类工具导出的动画
- 自动注册：`node scripts/gen-registry.mjs`

---

## 五、下一步该补的

1. **配乐**——33 个镜头全靠硬切，节奏再准也会显得干。需要定一首可商用的
2. **Tiny Charts**——华为 OpenTiny 的图表库还没接，但它需要搭页面再录屏，不如 SeeCode 直接
3. **音效**——转场、点击、数字滚动都需要细碎音效，现在完全没有
4. **封面**——还没做，是发布环节的第一步

---

## 六、一句话总结

这条片子最大的教训是：**所有"质感不行"的问题，根源都是素材不行**。

排版救不了没有素材的片子。素材够了，普通的排版也好看；素材不够，再花哨的动效也像 PPT。
