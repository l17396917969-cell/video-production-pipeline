（一句话描述用户/观众看到的问题）

- 判定：机器能算的条件（坐标、时长、颜色、帧数）。不能是"要舒服"。
- 修法：具体怎么做。
- 级别：硬门禁（脚本卡） / 自检（AI 逐条过） / 偏好（记录不卡）

## 已知问题

### 1. 字幕压住正文第二行

- 判定：字幕显示区间内，正文 bbox 与字幕 bbox 相交
- 修法：该段正文底边距加到 ≥ 字幕高 + 24px；或改成上方排版
- 级别：硬门禁

### 2. 组件同一屏幕出现两个大标题

- 判定：一屏内 fontSize ≥ 92 的元素超过 1 个
- 修法：删掉副标题或降档到 type.m
- 级别：硬门禁

### 3. 连续两句用同一个组件

- 判定：manifest 里 segments[i].component == segments[i+1].component
- 修法：中间换一个，或合并成一段
- 级别：硬门禁

### 4. 只记了选中的组件，没记排除的

- 判定：segment.candidates.length < 3
- 修法：补上另外两个候选和排除理由
- 级别：硬门禁

### 5. 一屏文字超过 12 行

- 判定：段落内换行数累计 > 12
- 修法：拆成两段，或删减
- 级别：自检

### 6. 英文术语读错

- 判定：`data/pronounce.json` 里没有该词
- 修法：加一条，实测
- 级别：自检

### 7. 段首出现约 0.4 秒近乎空屏

- 判定：每段第 0 帧起 12 帧内，画面平均亮度 < 20
- 修法：组件入场透明度从 12% 起（`kit.ts` 的 `fade()`），不要从 0 起
- 级别：自检

### 8. 深色主题被误判成黑屏

- 判定：用 `blackdetect` 时，背景 `#0A0A0C` 亮度约 25，会被当黑
- 修法：改用 `blackframe=amount=90:threshold=20`，只抓 Y<20 的真黑
- 级别：硬门禁（已改进 gate.mjs）

### 9. 中文标题机械断行

- 判定：标题断行处不在标点或空格上
- 修法：标题加 `wordBreak: 'keep-all'`
- 级别：自检

### 15. `sp()` 拼进模板字符串忘了 px

- 判定：`padding: \`${sp(16)} ${sp(12)}\`` 这类写法，整条样式静默失效
- 修法：模板字符串里每个值都要带 `px`；直接 `padding: sp(16)` 时 React 才自动补单位
- 级别：自检

### 16. 多实例共用 SVG mask / clipPath id

- 判定：整片里出现两处以上黑屏，只有最后一段正常
- 修法：id 用 `useId()` 生成，且去掉冒号
- 级别：自检

### 13. 整片像 PPT（最高优先级）

- 判定：任一镜头里，纯文字面积占比 > 50%，且全程没有一张真实截图/录屏
- 修法：画面主体换成真实素材（截图、录屏帧、产品界面），文字降级为压角标注；动效用镜头推移，不用元素飞入
- 级别：硬门禁（接片前人工卡）

### 14. 组件被当成"文字版式"

- 判定：组件的 props 里没有任何 `src` 类图片参数，且 desc 描述的是"文字怎么排"
- 修法：组件首先要是"素材容器"，其次才是版式。新组件先问：它装的是什么真实东西？
- 级别：自检

### 11. 分层图底座比顶部窄

- 判定：分层组件里最底层元素宽度 < 最顶层元素宽度
- 修法：宽度随层级递增，底座最宽（`76 + i * 8`）
- 级别：自检

### 12. 内容整块贴左，右侧大片空白

- 判定：主体右边缘 < 画宽 × 0.75
- 修法：外层 `alignItems: 'center'`，让整块居中，不要 flex-start
- 级别：自检

### 10. 组件检索搜不到中文

- 判定：查询里有中文且返回 0 个候选
- 修法：检索按 2-gram 切词，不足 3 个候选要补位
- 级别：硬门禁（已改进 find.mjs）

## 内容与叙事（手工判定，机器查不出来）

### C1. 纯黑底叠数字当成"高级"

- 现象：全屏黑底，中间一个大数字 + 一行说明
- 判定：画面里除了字，没有任何真实像素
- 修法：真实画面压暗到 30–40% 打底，字压在上面
- 代价：这不叫排版，叫拿黑底糊弄。观众一眼看出"没素材"
- 来源：T116 第一版，用户原话"纯黑背景太丑"

### C2. 抽象图形当开场

- 现象：几何标志描线、光圈放大、粒子扩散
- 判定：开场前 2 秒没有任何可读信息
- 修法：第一秒必须是真实画面或硬数字
- 代价：观众第一眼不知道你在讲什么，直接划走
- 来源：T115 六边形片头，用户原话"根本不吸眼球，非常失败"

### C3. 拿 GitHub 仓库页当第一个镜头

- 现象：开场就是 README、文件列表、分支数
- 判定：画面里同时出现文件树、issue 数、语言条
- 修法：项目名 + star 数滚动 + tagline；真实界面放第 3 秒之后
- 代价：仓库页信息密度太高，观众只看到"一堆看不懂的东西"
- 来源：调研 oss-showcase 规范 + 用户原话"第一秒用 github 页面很丑"

### C4. 文案和画面不对位

- 现象：台词说"它要的是 codex 这个命令"，画面却在放"支持哪些 agent"的标签墙
- 判定：把字幕读一遍，问"这句话该看见什么"，和实际组件对不上
- 修法：每段先写"这句台词指向的对象"，再选组件；选完再读一遍
- 代价：观众听着 A、看着 B，两边都记不住
- 来源：s13 标签墙错配，自查发现的

### C5. 界面太满还硬加标签

- 现象：想在一张信息密集的截图上加标注，标签放哪都压住真内容
- 判定：截图里连续文本区占比 > 50%
- 修法：改用纯括号（不加字），或者去掉标注让画面自己说话
- 来源：T106 在 T3 Code 界面上，标签压住 "Worked for 20s"

---

### C6. 自己画图表，追不上专业工具

- 现象：花时间在组件里手搓 3D 柱状图、层堆叠图，出来还是有"自制感"
- 判定：图表/架构类画面是自己用 div 拼的，不是外部工具生成后导入
- 修法：用 SeeCode 这类工具出 mp4（编辑部排版、真实动画），再用 T117 播放
- 代价：手搓的永远差一档——字号、网格、对齐、留白，专业工具都调好了
- 来源：用户原话"每一个分镜的素材，特效，质感都不行"

### C7. 整片纯黑底

- 现象：所有画面背景都是接近纯黑（#0A0A0C）
- 判定：连续 10 秒以上画面平均值 < 20/255
- 修法：底色提到 #14141A；浅色素材（图表/架构）穿插进来形成明暗节奏
- 代价：全片一黑到底，看久了压抑，也显廉价
- 来源：用户原话"整个页面太暗了"

### C8. 同一素材被反复用

- 现象：一张界面图在 3 个不同段落里出现
- 判定：统计 `props.src` 出现次数，同一张图 > 2 次就要警觉
- 修法：换不同的截图/录屏时间点，或者换素材类型
- 代价：观众第七分钟就看出你在凑
- 来源：用户原话"不同段之间用的视频素材重复了"
