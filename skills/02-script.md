# 写稿

**输入**：选题 + 角度
**输出**：`episodes/<期号>/script.md`，逐字稿 + 每句分镜提示

---

## 先想清楚：你是什么身份

这个决定稿子的上限，比任何写作技巧都重要。

| 身份 | 写出来的东西 | 观众反应 |
| --- | --- | --- |
| 体验博主 | 我装了两小时、踩了三个坑、终于跑通 | 又一个教程，划走 |
| 技术 KOL | 它在赌什么、赌对没有、边界在哪 | 这人真看过代码 |

**判据**：稿子里如果有一句是"我踩了什么坑"，问自己——这个坑是产品问题还是操作问题？操作问题（装不上、配不对）一句带过，产品问题（设计取舍）才值得展开。

---

## 第一步：读代码，不是读 README

**这是整个流程里最重要的一步，不能跳。**

README 是作者想让你看到的，代码是他实际做的。两者的差距，就是你的内容。

去读什么：

1. **核心模块**：`apps/server`、`packages/contracts`、`packages/shared` 里的主干
2. **配置项和数据模型**：字段名往往暴露真实复杂度（比如一堆 `cleanup` 字段 = 磁盘管理是痛点）
3. **内部文档**：`docs/internals/`、`AGENTS.md`、`CLAUDE.md`——这些是给贡献者看的，信息密度最高
4. **测试文件**：测试名会暴露边界情况（"回滚失败时必须拒绝操作"）

找什么：

- **硬规则**：代码里"必须这样，否则拒绝"的地方。这类规则背后往往是踩过坑
- **没被宣传的设计**：README 没提但代码里有大量逻辑的东西
- **复杂度高的地方**：字段最多、分支最多、注释最多的模块，通常就是真难点

**读完必须能回答**：这个项目最难的三个技术点是什么？分别在哪行代码？

---

## 第二步：找到一个"翻译"

最高级的写法，是把一条代码里的硬规则，翻译成一个产品态度。

例子（T3 Code）：

> 代码规则：provider 不支持回滚对话时，必须在动文件之前拒绝操作
> 翻译成：**AI 那边不支持回滚，就不许动你的文件**

这句话听着是工程细节，其实是产品态度——它承认了"代码能回滚，AI 的记忆不能"这个现实。

**每篇稿子至少要有这么一句。** 没有的话，说明代码还没读透。

---

## 第三步：结构

按这个顺序，八段左右：

| 段 | 干什么 | 例子（T3 Code） |
| --- | --- | --- |
| 1 | 数据 + 定位否定 | 五十万人在用，六万三千星。它不是编辑器 |
| 2 | 本质：它管的不是 X，是 Y | 它管的不是代码，是 AI 干完活留下的一堆烂摊子 |
| 3 | 最狠的设计在哪 | 每一轮对话结束，偷偷存一个快照，用隐藏 git ref |
| 4 | 转折：但这件事有个坑 | 你回滚了代码，AI 的记忆还在错误上下文里 |
| 5 | 翻译：把规则说成态度 | AI 那边不支持回滚，就不许动你的文件 |
| 6 | 边界：它不是万能的 | 并行不是默认开的，代价是盘会涨、子模块会乱 |
| 7 | 瓶颈：最后一个躲不掉的 | 三个任务跑完，九份改动还是你一个人审 |
| 8 | 趋势判断 | 竞争正在从谁写得快，变成谁管得住 |

**第 5 段是全片最值钱的地方**，写不出来就说明第 1 步没做到。

---

## 口吻

- 短句。一句一个意思。
- 用"但/问题在这/真正麻烦的是"，不用"首先/其次/最后"。
- 数字要具体：不说"很多人"，说"五十万人"；不说"很久"，说"两小时"。
- 专有名词第一次出现给一句解释，再往下就敢用简写了。

---

## 逐字稿格式

```
01 [4s] 五十万人在用，六万三千星。T3 Code 不是编辑器。
02 [5s] 它管的不是代码，是 AI 干完活留下的一堆烂摊子。
```

秒数是估算，配音后会按真实时长重算（`voice-episode.mjs` + `retime.mjs`）。

**连续三句超过 8 秒，观众就走了。**

---

## 禁止

- **禁止把安装/配置问题当重点**。那是教程的内容，不是点评
- **禁止从界面猜功能**。界面上能看到的，作者早就写在 README 里了
- **禁止没有代码证据的观点**。说"它做了 X"，要能指出在哪
- **禁止"今天我们来聊聊"** 这类开场
- **禁止整篇没有具体数字**
- **禁止超过 1500 字**

---

## 自检：写完问自己五个问题

1. 这篇稿子里，有几句话是**只有读过代码才说得出**的？
   → 少于 3 句，回去读代码
2. 有没有一句被"翻译"过的产品态度？
   → 没有，说明没找到硬规则
3. 有没有讲操作步骤？
   → 有，删掉或压成一句
4. 结论是判断还是总结？
   → "让并行可管理"是总结，"竞争从写得快转向管得住"是判断
5. 念一遍，像不像人说话？
